[size=4][b]What this is[/b][/size]

MW3 (2011) shipped on PC with [b]zero working controller input path[/b] — no [font=Courier New]xinput[/font]/[font=Courier New]dinput8[/font] import anywhere in the binary, no hidden setting to unlock. This is a from-scratch native controller [i]and enhancement[/i] project, not a keyboard/mouse-emulation mapper: analog movement, look, and most buttons drive the game's own real internal engine calls directly — the exact same fields and states a keyboard/mouse player already uses, just fed from a controller instead.

Every other "controller support" option for this game works by faking keyboard/mouse input underneath a mapper tool — poll, convert to a key/mouse event, OS input queue, then the game's own input processing. This project writes straight into the engine's real per-frame input path from inside the game's own process, on the game's own frame tick — no OS-level input event, no intermediate queue. That's the core advantage: input feel that matches native console analog input, not an approximation of it.

A small number of narrow, deliberate exceptions to that rule exist (documented, not hidden) for inputs where an exhaustive search found no locatable native trigger — those synthesize a real keypress instead of driving the engine directly. Everything else — including all of movement, look, and combat — drives real engine state.

[size=4][b]Feature status[/b][/size]

[color=#2ECC71][b]Confirmed working live by direct playtest:[/b][/color] analog movement and look, Sprint, Fire, true hold-to-aim ADS, Reload, weapon switch, Melee, Lethal, Tactical, Jump, Interact, the full Crouch/Prone stance ladder, and pause menu open/close.

[color=#F39C12][b]Build-verified and deployed, awaiting live confirmation:[/b][/color] Jump auto-stand, D-pad actionslot navigation, a fix for a sniper-class Fire/ADS report, the plugin API, and the custom Options screen (temporary open method pending a deeper fix).

[color=#E74C3C][b]Honestly not yet implemented on this line:[/b][/color] controller-glyph icons, on-screen hint prompts, the custom cursor, and the full visual-enhancement suite (render-scale, FSR sharpening, motion blur) that shipped on the prior 32-bit line.

[hr]

[size=4][color=#E74C3C][b]⚠ Do NOT use this with Plutonium multiplayer[/b][/color][/size]

Plutonium's own anti-cheat is confirmed to ban DLL injection and memory access — a 7-day ban on first offense, permanent after. This project's entire architecture (a proxy [font=Courier New]d3d9.dll[/font], function hooking) is exactly what that system is built to catch, regardless of this being input-only rather than a gameplay cheat. This is a real, confirmed risk, not theoretical. Supported: retail Steam Campaign/Survival only.

[size=4][b]Installation[/b][/size]

[color=#E74C3C][b]No file is currently available — see the notice at the top of this page.[/b][/color] Once a release ships: copy [font=Courier New]d3d9.dll[/font] into your MW3 install folder (the same folder as [font=Courier New]iw5sp.exe[/font]), launch the game normally, and check [font=Courier New]proxy_d3d9.log[/font] in that folder if anything looks wrong. Uninstalling is just deleting [font=Courier New]d3d9.dll[/font] — the base game files are never modified.
