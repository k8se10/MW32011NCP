## 2. Open thread A — DLSS hang on level load (user can't test DLSS right now)

History: `re_notes/x64_migration/vulkan_dlss_pipeline_research.md` item 17,
ROUNDS 13–19. ROUNDS 18 and 19 are this session's.

- **Last live data** (from a build *before* `c06e93e`): the composited DLSS
  picture looked correct and real frames were produced, but it hung before it
  became playable, sooner on heavier levels.
- **The two fixes waiting to be tested**:
  1. The output buffer had no `VK_IMAGE_USAGE_STORAGE_BIT`, so DLSS was writing it illegally (ROUND 18).
  2. DXVK memory defragmentation relocates images to new `VkImage` handles, so our tags went stale (ROUND 19).
- **What the log should show once built**:
  - `[x64-streamline-output] ... usage=0x1F layout=1 format=37`.
  - `post-flush re-resolve: ... image changed` lines on `color`, `output-color` or
    `motion-vectors` mean a relocation happened and was caught.
  - `post-flush re-resolve FAILED` means that frame was skipped, not evaluated with a stale tag.
- Watch FPS: depth now calls `GetVulkanImageInfo` on every
  `SetDepthStencilSurface`. In this DXVK's source that call is only field reads, no flush.
- **Attempt count**: CLAUDE.md §10.9 sets the "stop and ask the user" threshold
  at 5–6 genuine attempts on the same angle. This hang has had many rounds. If it
  still hangs after both fixes, **ask the user** before starting another round.

## 4. Open thread C — in-engine text/glyph drawing (RE done, nothing implemented)

Full write-up: `re_notes/x64_migration/engine_native_draw_x64.md`. Raw
decompiles: `re_notes/x64_migration/engine_draw_trace/`. Key facts:
- `FUN_14029a2b0` (already hooked as `Hook_DrawTextX64`) **is `UI_DrawText`**.
  Its `color1`/`color2` params are really horizontal/vertical alignment, and
  `param_10` is the real `float[4]` color. The hook's own parameter names are
  therefore misleading; rename them only as part of a real change.
- `ScrPlace_GetActivePlacement()` = `FUN_14008d8f0`. Font globals are
  `DAT_142604f90`..`fd0`. `Material_RegisterHandle` = `FUN_1401c4ba0`.
  `UI_DrawHandlePic` = `FUN_14028c2b0`.
- The backend supports the `^\x01` inline-icon escape. Its material lookup
  `FUN_1401c4b80` has exactly one caller, which makes it the hook point.
- Custom art needs a runtime-cloned material with our own texture at `GfxImage`+0.
  The recipe is in the doc's §4.
